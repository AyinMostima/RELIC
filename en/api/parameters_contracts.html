Parameters and Parameter Contracts

This page documents the canonical parameter-management API used by RELIC. UnifiedParameterManager is the only concrete parameter manager. It owns parameter lookup, validation, persistence, unit conversion, trainable parameters, caching, and snapshots. ParameterSpec is the canonical metadata contract for one parameter.

Important

There is no importable class named ParameterManager. In architecture prose, that name denotes the parameter-management role. Python code obtains the process-wide UnifiedParameterManager with get_global_manager(). Constructing UnifiedParameterManager(...) directly creates an independent manager, which must be injected explicitly where it is used.

Scientific FunctorBase subclasses must not call the global manager directly. They retrieve values only through self.get_parameter_value("key", required=...). Non-Functor infrastructure uses get_global_manager().get(...).

Each construction builds a new, independent manager; the class has no singleton hook. The process-wide manager is obtained only through get_global_manager(), and normal application code should use it. Code that needs a separate owner constructs one and injects it explicitly, for example through the parameter_manager argument of a Functor. An injected manager must expose database, its ParameterDatabase: dotted-name resolution in FunctorBase.get_parameter_value() and in the external coupling adapters calls relic.parameters.namespaces.is_declared_namespace(namespace, manager), which asks manager.database.declares_namespace(...). An independent manager never rewrites the process-wide variable name mapper.

Under the default packaged database (relic\parameters\database), 138 YAML files define 4,751 leaf entries (134 native relic tier files with 4,642 entries and 4 calibrated tier files with 109 entries), resolving after tier precedence to 4,643 active runtime parameters (810 learnable parameters with requires_grad=True). Two distinct precedence rules govern resolution: inside ParameterDatabase, later tiers override earlier tiers in the order relic, enabled calibrated scopes (global, regional, site_specific), and add_source(...) paths; inside a Functor, FunctorBase.get_parameter_value(..., source_order=("manager", "config")) queries "manager" (UnifiedParameterManager) before "config" (Functor-local overrides) by default.

get()

manager.get(
    key: str,
    default: Any = None,
    namespace: Optional[str] = None,
    units: Optional[str] = None,
    expected_type: Optional[type] = None,
    required: bool = False,
    bounds: Optional[Tuple[float, float]] = None,
) -> ParameterValue

Parameter

Purpose

key

Canonical or normalizable dot-notation parameter key.

default

Value returned when no parameter can be resolved and required is false.

namespace

Optional namespace prefix applied before key normalization.

units

Requested output units. The stored value is converted when the units are compatible.

expected_type

Require the resolved value to match a Python type.

required

Raise KeyError when the parameter is missing; when False, return default.

bounds

Optional read-time lower and upper bounds for a scalar value.

Returns the resolved value, not its metadata. A request for a namespace prefix (not a leaf key, without default, and with required=False) returns a nested mapping of the stored values of every key below <namespace>. that the manager holds or the database defines, the membership of get_namespace_parameters. The mapping is built at each read and belongs to the caller. Reading has no validation switch: a requested unit conversion is always checked, and any other keyword raises TypeError. Every successful read, including the direct storage path, is recorded in the access history that restart contracts read.

Raises:

  • KeyError when required=True and the key cannot be resolved.

  • TypeError when expected_type is incompatible with the resolved value.

  • Unit-conversion or validation exceptions when the requested conversion or validation cannot be completed.

For a Python scalar or one-element Tensor, bounds clamps the returned value and emits UserWarning when clamping occurs. It does not clamp multi-element Tensors.

get_parameter()

manager.get_parameter(
    key: str,
    namespace: Optional[str] = None,
) -> Optional[ParameterSpec]

Returns the full ParameterSpec or None. This method is for metadata inspection, including units, bounds, references, provenance, and requires_grad. A key that the manager does not hold yet is read from the database, which lazily loads the parameter files whose declared namespace owns the key (see ParameterDatabase); a learnable value is then registered with the manager’s PyTorch parameter collection.

Mutation and persistence

manager.set_value(
    key: str,
    value: ParameterValue,
    units: Optional[str] = None,
    validate: bool = True,
    notify: bool = True,
) -> None

Updates a value, optionally validates it, invalidates affected caches, and notifies registered observers. key must name a registered parameter (loaded or in the database): an unknown key raises KeyError and changes nothing, so a misspelled key never becomes a new parameter. A new parameter is registered first with register_parameter(...). Validation failures raise ValueError. Out-of-bounds behavior is controlled by BoundsPolicy and the manager’s validation configuration; an invalid RELIC_BOUNDS_POLICY or RELIC_UNIT_VALIDATION_MODE environment value raises ValueError when the manager is created. units names the unit of value: the value is converted into the declared unit of the specification, which is never replaced; the dimensionless aliases "1" and "dimensionless" need no conversion, and a pair the unit owner cannot convert raises ValueError without writing. set_batch(updates, validate=True, notify=True) commits the whole batch (or restores every owner on a failure), then notifies every changed key; callback failures of all keys are raised together as one ExceptionGroup afterwards, and the changes stay committed.

manager.set_parameter(
    spec: ParameterSpec,
    tier: str,
) -> None

Persists one complete specification to the database tier and sets that parameter’s specification, stored value and live binding together; no other specification is loaded into the manager. An existing binding of the same shape and dtype keeps its nn.Parameter object, gradient flag, and device and takes the new value in place; a specification that is no longer learnable loses its binding. A learnable specification without a tensor form raises TypeError before anything is written. spec must be a ParameterSpec; otherwise TypeError is raised. Loading the whole database (preload_all, a new database_path) gives every specification its stored value and every learnable specification its binding in the same way.

manager.register_parameter(spec: ParameterSpec) -> None

Registers a specification in the existing manager and storage layer. This is a lower-level registration operation used by database and extension loading. It does not create another parameter owner. register_parameter and set_parameter(spec, tier) use the same bind_learnable_value rule, including database re-registration: matching shape and dtype preserve the live binding object, gradient flag, and device and copy the value in place. Changed shape or dtype creates a new binding; a non-learnable specification has none. set_parameter requires the destination tier explicitly.

manager.snapshot() -> Dict[str, Any]
manager.restore(snapshot: Dict[str, Any]) -> None
manager.create_snapshot(description: str = "") -> ParameterSnapshot
manager.restore_snapshot(snapshot: ParameterSnapshot) -> None
manager.get_diff(snapshot: ParameterSnapshot) -> Dict[str, Tuple[Any, Any]]
manager.diff(other_snapshot: Dict[str, Any]) -> Dict[str, Any]

The manager snapshot keeps each owner of parameter state apart and exactly as it is: parameters holds the serialized specifications with their declared values (type and dtype kept), storage_snapshot the storage’s own snapshot of the stored values (a specification whose value is not stored yet stays without one), nn_values a copy of every live learnable nn.Parameter value (an optimizer may have moved it away from the declared value) and nn_requires_grad its gradient flag, next to the device, the validation settings and the unit issues. restore() validates the whole snapshot before it changes anything: it requires a parameters mapping, stored values that agree with their specifications, gradient flags only for learnable specifications, and one live value per flag with the shape and dtype of its specification; otherwise it raises ValueError. It then restores the stored values, the specifications, the live values (copied into the existing bindings, across devices, without replacing them; bindings created after the snapshot are removed) and the settings, so every value with its type and dtype, and every specification, equals its state at snapshot time.

create_snapshot() captures every parameter’s value exactly (its stored value, or its declared value while none is stored) and the live learnable values in metadata["nn_values"]; restore_snapshot() writes those values back, without validation, clamping or conversion, to the parameters that still exist and copies the live values into their bindings. Parameters registered after the snapshot are kept. get_diff(), diff() and the experiment diff compare resolved values: the live learnable value over the stored or declared value, which is the value manager.get(...) returns.

Global manager functions

get_global_manager()

get_global_manager(
    preload_all: bool = False,
    warmup_cache: bool = False,
) -> UnifiedParameterManager

Returns the process-wide canonical manager. The first call creates it under a reentrant lock, calls initialize(), and refreshes the process-wide variable name mapper from it; if either step fails, the global manager is reset and the error is raised. Later calls return the same object; a later call with preload_all=True preloads it when it was not preloaded. Such a late preload adopts the database specifications of the keys the manager does not hold yet; a key it already holds (loaded on demand, registered, or written with set_value) keeps its specification, stored value and live binding. initialize() loads nothing: a manager constructed with preload_all=True holds the whole database when its constructor returns, and a value written or a learnable binding moved before initialize() is kept. A database switch (configure with a new database_path) unit-checks every specification of the new database under the manager’s unit validation mode (check-only records an issue, strict raises before anything is adopted), replaces the held specifications, stored values and binding values with those of the new database, then clears the query cache and the unit-conversion cache as a whole (also when the load fails part way), so no lookup cached from the previous database survives the switch. A switch that fails keeps the previous database_path and database, the ones that define the held specifications.

reset_global_manager()

reset_global_manager() -> None

Clears the process-wide manager instance. This is a lifecycle and isolation operation, not a routine scientific workflow operation.

Implementation: relic.parameters.spec.ParameterSpec

Constructor

The displayed empty collections are produced by dataclass factories; instances do not share mutable defaults. units, dtype, bounds, and category have no default: a numeric dtype declares a (lower, upper) interval and writes an unbounded side as -inf or inf (bounds=(-inf, inf) is explicitly unbounded); bounds=None states that no interval applies and is accepted only for a non-numeric dtype (text, boolean switch, enumeration, list or mapping). relic.parameters.spec.parameter_bounds_error(bounds, dtype) is the one rule: ParameterSpec raises ValueError on a violation, and has_complete_parameter_metadata, the structural parameter audit and the parameter YAML schema read the same rule.

A list or tuple dtype may declare one [minimum, maximum] pair of numbers per component in place of a single scalar interval, for example [[223.15, 273.15], [323.15, 373.15]] for a two-component value. relic.parameters.spec.componentwise_bounds_errors(value, pairs) is the one rule for such a declaration: the value is a list or tuple with one finite real component per pair, each inside its closed pair. validate_value() returns the violations, a validated set_value(...) and a validated FunctorBase.get_parameter_value(...) raise ValueError, and no component is clamped. A flat (lower, upper) interval on a list value is not applied to its components.

A numeric parameter declares its bounds endpoints, value, and default as numbers. parameter_bounds_error rejects textual numeric endpoints, and ParameterSpec rejects textual numeric values or defaults; neither is converted by from_dict. With PyYAML’s YAML 1.1 rules, write 1.0e+7 or 1.0e-6: 1.0e7 and 1e-6 are strings and are rejected.

validate_value()

spec.validate_value(value: ParameterValue) -> List[str]

Returns validation messages without raising for ordinary invalid values. Checks include categorical membership, finite numeric values, scalar bounds, non-negative biological rates and concentrations, and physically valid absolute temperatures.

Tensor conversion

spec.to_tensor(
    device: Optional[torch.device] = None,
) -> torch.Tensor

spec.from_tensor(tensor: torch.Tensor) -> None

to_tensor() maps declared boolean, integer, and floating dtypes to PyTorch. String and categorical values raise TypeError. A non-floating Tensor cannot retain gradients; conversion failure raises TypeError.

from_tensor() accepts only a scalar Tensor. A non-Tensor raises TypeError; a non-scalar Tensor raises ValueError.

Mapping and serialization interface

ParameterSpec implements Mapping[str, Any] and provides:

spec.to_dict() -> Dict[str, Any]
spec.model_dump(**kwargs) -> Dict[str, Any]
ParameterSpec.from_dict(data: Dict[str, Any]) -> ParameterSpec

from_dict() requires value, normalizes category, dtype, tags, bounds, and categorical values, and moves selected additional metadata into provenance.

to_dict() and model_dump() also emit default, in the same Tensor wire format as value, and allowed_values, as a list or None. from_dict() decodes a Tensor-encoded default and normalizes allowed_values to a list or None, so both fields round-trip.

ParameterSchema

Implementation: relic.parameters.serialization.ParameterSchema

Stable public import:

from relic.parameters import ParameterSchema

Status: stable serialization helper. It owns the parameter interchange envelope, not parameter lookup, per-entry metadata, or database persistence. The class has no constructor parameters and is intended as a namespace for its version and static methods.

from relic.parameters import ParameterSchema

assert ParameterSchema.VERSION == "1.0.0"

The canonical envelope has a parameters mapping. Each member is a mapping that contains at least value. version, timestamp, and metadata may accompany it.

validate_schema()

ParameterSchema.validate_schema(
    data: Dict[str, Any],
) -> bool

Returns True only when:

  • data contains parameters;

  • parameters is a mapping;

  • every parameter entry is a mapping containing value.

It returns False for an incomplete canonical mapping. The current method is a lightweight structural check; it does not validate all ParameterSpec fields, units, bounds, or provenance. Inputs outside the declared mapping contract may raise ordinary Python type errors.

migrate_schema()

ParameterSchema.migrate_schema(
    data: Dict[str, Any],
    from_version: Optional[str] = None,
) -> Dict[str, Any]

Raises ValueError when data is not a mapping, when parameters is not a mapping, or when the canonical parameters field is missing.

Current implementation limits:

  • Flat legacy parameter maps are rejected without migration.

  • from_version is accepted by the signature but does not currently select a version-specific migration path.

  • ParameterSchema must not be treated as a second ParameterSpec schema or validation registry.

ParameterDatabase

ParameterDatabase(
    base_path: Path,
    validator: Optional[ParameterValidator] = None,
)

The database owns two precedence tiers:

  • relic: native framework parameters.

  • calibrated: calibration and optimized values.

Construction creates the relic and calibrated tier directories under base_path and initializes an empty parameter cache and a per-file header cache; it builds no file index. Every read follows one load plan:

  1. the native relic files (the base tier);

  2. the enabled calibrated scopes global, regional, and site_specific, in that order (RELIC_CALIBRATED_SCALES selects scopes, top-level calibrated snapshot files take part only with RELIC_INCLUDE_CALIBRATED_SNAPSHOTS=1, and RELIC_SKIP_CALIBRATED=1 excludes the calibrated tier);

  3. the sources added with add_source().

Later entries take precedence, and a key defined in two base-tier files raises ValueError naming both files. The namespace of a YAML file is its top-level namespace: header line, read from the raw bytes and cached by modification time and size; file and directory names play no role. JSON files and YAML files without that header are read only by the full loads. Primary methods include:

database.load_all() -> Dict[str, ParameterSpec]
database.load_all_with_priority(
    source_priority: List[str],
) -> Dict[str, ParameterSpec]
database.get_parameter(key: str) -> Optional[ParameterSpec]
database.set_parameter(
    spec: ParameterSpec,
    tier: str = "calibrated",
) -> None
database.add_source(source_path: Path) -> None
database.load_namespace(namespace: str) -> None
database.declares_namespace(namespace: str) -> bool
database.declared_namespaces(
    directory: Optional[Path] = None,
) -> List[str]

get_parameter(key) returns a cached specification directly. Otherwise it loads the files whose declared namespace is a dot prefix of the key, together with every file of a related (ancestor or descendant) namespace, in full-load precedence. If that does not define the key, it runs load_all(); with fail_on_validation_errors set, it raises KeyError instead. That flag comes from RELIC_FAIL_ON_PARAMETER_VALIDATION (1, true, or yes) or, when that variable is unset, from a true CI variable or a RELIC_ENV of ci, prod, or production.

load_namespace(namespace) reads the files of related namespaces in the same way, declares_namespace(namespace) reports whether a participating file declares the namespace, an ancestor, or a descendant, and declared_namespaces() lists the declared namespaces in load order. load_all_with_priority(source_priority) accepts only relic and calibrated, highest precedence first, reads those tiers of the load plan without the additional sources, raises ValueError for any other name, and leaves the cache unchanged. add_source() raises FileNotFoundError for a path that does not exist.

Application code normally reaches this object through UnifiedParameterManager.database. Direct construction is appropriate only for controlled infrastructure that intentionally owns a database root.

ParameterStorage

ParameterStorage() -> ParameterStorage

Provides thread-safe in-memory CRUD, namespace indexing, access statistics, and immutable snapshots.

storage.get(key, default=None) -> Optional[ParameterValue]
storage.set(key, value) -> None
storage.delete(key) -> bool
storage.exists(key) -> bool
storage.list(namespace=None, pattern=None) -> List[str]
storage.get_all() -> Dict[str, ParameterValue]
storage.snapshot(description="", *, parameters=None, metadata=None) -> ParameterSnapshot
storage.restore(snapshot: ParameterSnapshot) -> None
storage.diff(snapshot1=None, snapshot2=None) -> Dict[str, Tuple[Any, Any]]

storage.list(namespace=...) returns every key below "<namespace>." (children and deeper descendants) with one rule for every namespace; a key of a sibling prefix (a.bc.x for namespace a.b) is never returned.

UnifiedParameterManager.delete(key) removes the specification, the storage value and any registered nn.Parameter, then clears the query cache and the unit-conversion cache as a whole, so no cached lookup of the deleted key or of its namespace/unit variants survives the deletion. storage.snapshot() captures the stored values, or the explicit parameters values without changing live storage, each with its type and dtype; metadata is recorded with the snapshot. storage.restore(snapshot) replaces the stored values and then notifies the manager. The manager requires a specification for every restored value, the loaded one or the database one; a value without any specification raises KeyError, and no specification is invented. It brings specification values and live bindings in line with the restored values and drops the specifications and bindings of parameters absent from the snapshot. When a restore callback raises, its error propagates and the storage takes back the values it held before the restore. manager.restore(snapshot) writes the stored values directly and sets the snapshotted specifications exactly itself.

This is the manager’s value layer, not a public alternative to UnifiedParameterManager.

Physical constraint integration

Stability and ownership

PhysicalConstraintManager, ConstraintSpec, and ConstraintType are defined in:

relic\coupling\scales\physical_constraint_manager.py

They are not exported by relic.coupling.scales or relic.coupling. Their direct module path is the canonical infrastructure integration path, not a general package-root public API.

Each StateManager owns its physical-constraint manager. It first uses an explicit physical_constraint_manager= constructor injection; otherwise its read-only physical_constraint_manager property lazily constructs, initializes, validates, and caches one instance for that StateManager:

from relic.core.state import StateManager

state_manager = StateManager(autoload_contract_registry=False)
constraint_manager = state_manager.physical_constraint_manager
assert constraint_manager is not None

There is no module-global physical-constraint getter or setter. Scientific Functors propose their state updates through the existing contract and do not create competing constraint owners. Infrastructure that needs explicit construction uses the same class and its normal lifecycle.

Conservation guardian

Stability and ownership

ConservationGuardian is the canonical fourth-layer domain budget checker named by the architecture, but it is not re-exported from relic.validation. Use the direct module path only for validation infrastructure:

from relic.validation.conservation_guardian import (
    BudgetCheckResult,
    ConservationGuardian,
)

StateManager owns commit-time state ledgers and invokes the guardian through its conservation integration. ConservationGuardian is a non-blocking diagnostic checker; it is not another StateManager, ledger, generic validation result, or scientific process.

    flux_out: Dict[str, Union[torch.Tensor, float, int]],

The domain balance is:

\[ \Delta S_{\mathrm{expected}} = \left(\sum F_{\mathrm{in}} - \sum F_{\mathrm{out}}\right) \Delta t. \]

The threshold is:

\[ \tau = \mathrm{atol} + \mathrm{rtol} \lvert\Delta S_{\mathrm{expected}}\rvert. \]

A failed budget logs an error and returns passed=False; it does not raise merely because the budget failed. Registry, conversion, or Tensor failures can still propagate. check_domain() does not populate invariant_drift; that diagnostic is computed separately.

    flux_vector: Dict[
        str,
        Union[torch.Tensor, float, int],
    ],
    dt: float,
) -> float

Returns zero for an empty coefficient row or empty flux vector. Otherwise the coefficient count must equal the number of flux entries; a mismatch raises ValueError.

Scientific modules must not reproduce these tolerance and budget loops in their forward() methods. Local checks remain owned by FunctorBase, commit-time ledgers by StateManager, and domain diagnostics by ConservationGuardian.

Physical constants and anti-redundancy rules

Physical constants have one database owner:

relic\parameters\database\relic\physical\constants.yaml

Non-Functor infrastructure reads them through:

from relic.utils.physical_constants import get_physical_constant

kappa = float(get_physical_constant("von_karman_constant"))
assert 0.39 < kappa < 0.42

Do not duplicate physical constants in Python or domain parameter files. Do not add another manager, parameter accessor, cache, database facade, or compatibility wrapper. In particular, removed access chains such as get_parameter_by_path(), _require_parameter(), require_parameter_value(), and ParameterAccessorMixin are not part of the public architecture.
