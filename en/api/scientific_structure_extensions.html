Scientific Structure and Extension APIs

This reference covers four separate API families:

  1. DEC typed structural views.

  2. IPHS structure, reaction advancement, and equivalence certificates.

  3. Python Functor extensions described by relic_extension.yaml.

  4. C ABI coupling plugins hosted through PluginHost.

These families interoperate with existing RELIC owners. They do not introduce another StateManager, ParameterManager, simulator, compiler, port schema, or registry.

Important

The Python extension loader and the C ABI coupling-plugin host are different protocols. A Python scientific extension implements one of the four bridge classes. A C ABI plugin crosses a language boundary and is wrapped by PluginFunctorAdapter. Their manifests, validation paths, and lifecycle roles must not be conflated.

DiagnosticSpec

DiagnosticSpec(
    name: str,
    input_state_vars: Tuple[str, ...],
    output_units: str,
    diagnostic_kind: str,
    writes_state: bool = False,
    feedback_port: Optional[str] = None,
    metadata: Mapping[str, Any] = {},
)

DiagnosticSpec remains read-only: writes_state must be the exact boolean False, even with a feedback_port. That declaration never authorizes a state write. Managed feedback has a separate existing non-diagnostic owner: relic.coupling.observation.state_feedback.ObservationStateFeedbackFunctor. It forms the direct-observation innovation d=y-x, checks abs(d)/sqrt(B+R)<=nu_max, and proposes x_a=x+B/(B+R)*d as a REPLACE update through StateManager. The target SCM must authorize observation_state_feedback; its gain, increment, and analysis variance are diagnostics on the observation route. Tower/support observation operators remain read-only. This scalar identity-observation binding is not a general assimilation algorithm or authorization to mutate diagnostics.

Number of cells for each topological degree.

Discrete exterior derivative matrices keyed by source degree.

Constructor validation checks basic identities, dimensions, and derivative matrix shapes.

bundle.validate_complex(
    tol: float = 0.0,
    *,
    strict: bool = False,
) -> Dict[Tuple[int, int], float]

The method evaluates:

\[ D_{k+1,h} D_{k,h} = 0. \]

It returns residual norms keyed by the composed degree pair. A negative, non-finite, or non-numeric tolerance raises ValueError.

With strict=True, the bundle must contain the complete derivative sequence and all support tensors on one device. Boundary masks must be binary, orientations must be -1 or 1, and primal and dual measures must be positive. Missing data, invalid shapes, non-finite values, or residuals above tol raise ValueError.

Strict validation also requires integer-valued incidence within the exact integer range of the dtype, D[0] @ 1 = 0, 0 <= tol < 0.5, no boundary mark on top-degree cells, and a boundary subcomplex closed under the boundary operator. Non-strict validation checks only the consecutive D pairs actually supplied. coboundary_matrix(k), boundary_matrix(k) (the transpose view of the unique D owner), trace_matrix(k), and typed_stokes_audit(alpha, chain) are also public; the Stokes audit evaluates one pairing \(\langle D_k\alpha,c\rangle-\langle\alpha,\partial_{k+1}c\rangle\) and does not prove mesh provenance or boundary-mask completeness.

Construction resolves each None tolerance through ParameterManager; a missing key raises. It rejects invalid matrix types, rank, shape, finite values, empty keys, invalid tolerances, or invalid complex dimensions.

hodge.validate(
    *,
    passive: bool = True,
    strict: bool = False,
    parameter_resolver: Optional[Callable[[str], Any]] = None,
) -> Dict[str, Union[float, bool, str]]

Strict validation requires:

  • one complex and physical domain;

  • opposite primality and complementary form degrees;

  • one orientation and boundary convention;

  • resolvable, non-wildcard parameter and metric keys;

  • a parseable unit relation in which operator_units * domain.units is convertible to codomain.units.

A strict passive operator must be square, declare role (metric_hodge or material_hodge) and definiteness, and use tolerances not above sqrt(machine epsilon) for its dtype. Every passive square matrix must be symmetric and positive semidefinite within tolerance. A strict metric_hodge must be positive_definite; a strict positive_semidefinite operator must be a material_hodge with a linearly independent kernel_basis whose width equals the numerical nullity and whose image matrix @ kernel_basis vanishes within kernel_rtol. Violations raise ValueError. These checks concern the supplied matrix value, not mesh provenance or refinement convergence.

Field

Purpose

Constructor validation (__post_init__)

Chain-map identifier used in output cochain labels and diagnostics.

close_within(
    first: LinearChainMap,
    second: LinearChainMap,
    epsilon: float,
) -> bool

apply(cochain) requires cochain.space == self.source (ValueError otherwise) and evaluates \((M x) \cdot u\) into a TypedCochain on self.target preserving time and provenance. compose(first) forms \(M_2 \circ M_1\) when first.target == self.source, multiplying matrices in float64 and multiplying unit_factor values. preserves_ledger(...) checks \(\max \lvert C_{\mathrm{target}} (u M) - C_{\mathrm{source}} \rvert \le \tau\), resolving validation.iphs.chain_map_ledger_tolerance from get_global_manager() when tolerance is None. equals(other) tests exact equivalence of spaces, unit_factor, and float64 matrices, whereas distance(other) returns the operator 2-norm \(\lVert u_1 M_1 - u_2 M_2 \rVert_2\) on identical spaces and close_within(first, second, epsilon) evaluates that reflexive, symmetric, non-transitive distance bound.

import torch
from relic.computation.operators.dec import (
    CochainSpaceSpec,
    LinearChainMap,
    TypedCochain,
    close_within,
)

fine = CochainSpaceSpec(
    complex_id="col_2",
    degree=2,
    primality="primal",
    n_dofs=2,
    units="kg",
    extensivity="extensive",
    physical_domain="soil",
    semantic_name="soil_carbon_layer",
    orientation_convention="right_handed",
)
coarse = CochainSpaceSpec(
    complex_id="col_1",
    degree=2,
    primality="primal",
    n_dofs=1,
    units="g",
    extensivity="extensive",
    physical_domain="soil",
    semantic_name="soil_carbon_total",
    orientation_convention="right_handed",
)
agg = LinearChainMap(
    name="sum_kg_to_g",
    source=fine,
    target=coarse,
    matrix=torch.tensor([[1.0, 1.0]], dtype=torch.float64),
    unit_factor=1000.0,
)
out = agg.apply(TypedCochain(name="c", values=torch.tensor([1.5, 2.5]), space=fine))
ok, residual = agg.preserves_ledger(
    source_ledger=torch.tensor([[1000.0, 1000.0]]),
    target_ledger=torch.tensor([[1.0]]),
    tolerance=1e-12,
)
assert ok and residual == 0.0 and float(out.values.item()) == 4000.0
assert close_within(agg, agg.compose(LinearChainMap.identity(fine)), 1e-12)

structure.validate(
    *,
    required_level: Optional[int] = None,
    energy_effort: Optional[torch.Tensor] = None,
    port_input: Optional[torch.Tensor] = None,
    state: Optional[torch.Tensor] = None,
    energy_value: Optional[torch.Tensor] = None,
    entropy_value: Optional[torch.Tensor] = None,
    entropy_effort: Optional[torch.Tensor] = None,
    reaction_rates: Optional[torch.Tensor] = None,
) -> Dict[str, Union[float, bool, str]]

The base validation checks:

\[ J + J^\mathsf{T} = 0, \qquad R = R^\mathsf{T}\succeq0, \qquad M = M^\mathsf{T}, \qquad M \succeq 0. \]

Strict structure verification and governed process acceptance are separate checks. required_level=4 selects formulation="dissipative_ph" with M=0 and PSD R; required_level=5 selects formulation="generic" with R=0. Neither formulation silently adds the other’s dissipative term.

For Level 4, explicit energy_effort alone supplies the single-point structural pre-gate. A bound state=x and energy_value=H derive dH/dx through autograd and can return runtime_verified_level=4 with process_level_status="runtime_point_verified". A nonzero reaction also requires reaction_rates and storage_kind: total_energy requires e_H^T N r=0, while free_energy requires e_H^T N r<=0. An absorbed reaction must satisfy N r=-R e_H and is not added a second time. These reaction pairings are implemented at the operator level; no production dPH reaction process is currently bound. Level 4 runtime points with external port columns remain unavailable because port_input cannot accompany bound potentials; internal port columns eliminated through C/D feedback are accepted.

For Level 5, the reversible operator must use an executable Jacobi basis: zero_field (J(x)=0; every local J and reversible feedback C exactly zero before conversion and assembly), constant_field (constant J), or state_field (callable J(x) with skew and Jacobi residuals checked on the declared samples and again at the runtime point: the bound state, or the first declared sample when explicit efforts are supplied; residuals above skew_tol or jacobi_tol are rejected, and the audit reports runtime_point_skew_residual, runtime_point_jacobi_residual, and runtime_point_jacobi_point). This is finite-point evidence, not a continuum proof. matrix_snapshot, a constant label, or a text reference does not prove a global field identity. Bind the actual state and energy/entropy potentials, and supply reaction rates for a declared N. The runtime audit verifies J e_S=0, M e_E=0, nonnegative entropy production, closed-reaction energy/entropy pairings, and, when absorbed, M e_S=N r. It can return runtime_verified_level=5 and process_level_status="runtime_point_verified". Level 5 runtime points with declared port columns remain unavailable; no production process binds a nonzero field.

A runtime-point result alone is not a process certificate. Pass it as runtime_point_audit to the existing certificate owner together with the governed_execution witness: entry="FunctorBase.__call__", the executed Functor, committed non-diagnostic variables, and a positive accepted step count. Missing witnesses retain runtime_binding="descriptive" and the process_bound_runtime_unavailable [N] issue; inconsistent witnesses fail. The witness is a mapping the caller builds from an executed step; the certificate owner validates its fields and does not query StateManager provenance, so it is inspectable evidence, not an automatically issued certificate. A runtime point audits the continuous-time drift at the bound pre-step state, not the discrete time step. The bounded production selections are closed one-dimensional FickianDiffusion(strict_runtime_point=True) at Level 4 and the closed constant-volume NO+O3 selection ChemistryFunctor(physical_boundary="closed_constant_volume") at Level 5. Their runtime-point certificates record these selections in the certificate field constructor_selection. Other configurations do not inherit these claims. The Fickian selection requires one unbatched one-dimensional state with at least two cells, finite positive diffusivities, and a zero-flux or periodic boundary; its storage is a quadratic norm in kg2 m-6, not joules, and a nonzero source_term is rejected before integration, because the audited drift is source-free. The NO+O3 selection requires positive amounts, positive affinity, a temperature inside the declared NASA7 interval, fixed volume, no heat or work exchange, and forward mass action. The main certificates of both classes remain Level 3.

Invalid levels and failed structural checks raise ValueError.

) -> IPHSStructureSpec

Contributions may be mappings or objects implementing contribute_iphs_structure(). Local operators are embedded into the declared global state basis:

\[ J = \sum_i \iota_i J_i \iota_i^\mathsf{T} + G C G^\mathsf{T}, \]
\[ R = \sum_i \iota_i R_i \iota_i^\mathsf{T} + G D G^\mathsf{T}, \qquad M = \sum_i \iota_i M_i \iota_i^\mathsf{T}. \]

port_interconnection_C must be skew-symmetric. port_dissipation_D must be symmetric positive semidefinite and contributes only to the energy resistance R, producing -G D G^T e_H in the dissipative-pH drift. It never augments GENERIC M; formulation="generic" together with port_dissipation_D raises ValueError. Strict assembly requires at least one contribution and a traceable runtime owner or source node. required_level is applied only when validate=True. The assembler resolves None for skew_tol, psd_tol, and degeneracy_tol from validation.iphs.skew_tolerance, validation.iphs.psd_tolerance, and validation.iphs.degeneracy_tolerance before it checks C and D, and passes the Poisson-field arguments unchanged to IPHSStructureSpec, where jacobi_tol=None reads validation.iphs.jacobi_tolerance.

Contributions are embedded by exact state_vars name: contributions naming the same variable act on one coordinate, and different names are never aliased or unit-converted. Declared energy/entropy gradient contributions are summed coordinatewise; the assembler constructs no H, E, or S functional, effort, affinity, or shared-state equivalence. It has no storage_kind argument, so the Level 4 reaction pairing needs a directly constructed IPHSStructureSpec.

Every argument is keyword-only; poisson_operator and reaction_representation have no default and are required. The graph-metadata compile path (iphs_assembly in graph metadata) forwards poisson_operator and reaction_representation, both required (a declaration without one raises ValueError naming the missing field), and, when declared, poisson_field, poisson_domain, jacobi_tol, skew_tol, psd_tol, and degeneracy_tol. poisson_field must be an importable package.module:attribute reference, resolved at compile time to a callable; poisson_domain must be a non-empty list of numeric state vectors of equal length and becomes a float64 (m, n) tensor. These three keys are accepted only with poisson_operator constant_field or state_field. A declared tolerance must be a number (a null, string, bool, or list is refused); its range is checked by the structure. An omitted tolerance selects the ParameterManager default. A refused declaration makes the IPHS assembly audit report passed=False with the reason. A state_field structure can therefore be compiled from graph metadata.

Invalid contributions raise TypeError; duplicate or unknown state variables, shape mismatches, missing G, or invalid port matrices raise ValueError.

Coupling manifest contract

Both probe and negotiation return a JSON object. Required top-level fields are name, interface_version, metadata, and ports.

Each port declares:

Field

Accepted values and purpose

Non-empty state or coupling-port name

direction

in, out, or inout

INT32, INT64, F32, F64, STR, or BYTES

Optional dimensions used for buffer allocation and scale inference

host.load(path: str) -> Dict[str, Any]

Loads the library, binds the three required symbols, validates its declared interface version, and returns a lifecycle receipt including ABI metadata.

  • A missing file raises FileNotFoundError.

  • A native loading failure propagates from ctypes.

  • Missing required symbols raise RuntimeError.

  • An incompatible declared interface version raises PluginABIError and releases the library before exchange.

  • Loading an already loaded or retired host raises PluginLifecycleError.

host.retire() -> Dict[str, Any]
host.drain(timeout: Optional[float] = None) -> bool
host.unload(*, drain_timeout: Optional[float] = None) -> Dict[str, Any]
host.reload() -> Dict[str, Any]

Retirement rejects new native calls while calls already in flight continue. drain waits for their completion. unload releases the library only after draining; a timeout returns released=False and drained=False, retaining a retired host whose unload can be retried. A repeated unload after successful release is rejected. reload drains and reopens the same path. Read-only state, loaded, inflight_calls, completed_calls, abi, and receipts expose the current lifecycle and its outcomes. Returning from a C entry point is the completion signal available to this ABI.

host.probe() -> Dict[str, Any]
host.negotiate(
    host_capabilities: Dict[str, Any],
) -> Dict[str, Any]

Both require a loaded plugin. A nonzero plugin return code, empty JSON, or an unloaded host raises RuntimeError. Invalid JSON propagates its parser error; a non-object JSON payload raises ValueError.

host.exchange(
    port_name: str,
    buffer: Any,
    timestamp: float,
) -> int

Supported buffers are:

  • numpy.ndarray

  • torch.Tensor

  • memoryview

  • bytearray

The method returns zero on success. Unsupported buffer types raise TypeError; an empty buffer raises ValueError; a nonzero plugin return code raises RuntimeError.

    host_capabilities: Optional[Dict[str, Any]] = None,
) -> Dict[str, Any]

Loads the library, validates the probe manifest, negotiates host capabilities, validates the agreed manifest, stores ports, and rebuilds Functor metadata. Invalid manifests or unresolved spatial scale raise ValueError; native host failures propagate.

adapter.get_dependencies() -> List[str]

The adapter does not override get_dependencies(). It inherits the ScaleCouplingFunctor bridge default, which returns the names declared on the instance through config["dependencies"], set_dependencies(...) or add_dependency(...), in declaration order and without duplicates. The list is empty only when nothing is declared. When GraphExecutor builds a node from a graph step that has input links, it calls set_dependencies(...) with the sorted source-node names of those links. This replaces the earlier instance list, so the graph links become the adapter’s dependencies.

    time: float,
    dt: float,
    **kwargs: Any,
) -> Dict[str, UpdateItem]

The adapter initializes lazily, exchanges each declared port, and lowers outputs with the existing FunctorBase.wrap_update() path.

Missing required input ports raise KeyError. Host, manifest, conversion, and exchange errors propagate. Ports with no name or an unsupported direction are skipped by the current compatibility path.

PluginFunctorAdapter is coupling infrastructure and subclasses the ScaleCouplingFunctor bridge class, which reaches FunctorBase. It is not a template for Python scientific modules. A Python scientific extension must still follow:

Scientific abstraction -> bridge class -> FunctorBase -> ParameterManager

Anti-redundancy boundary

The APIs on this page compose with current owners:

  • DEC views use existing SSOT and state contracts.

  • IPHS assembly uses declared runtime contributions and existing ports.

  • IPHS levels are owned only by IPHSEquivalenceCertificate.

  • Python extensions register through the existing simulator and NodeRegistry.

  • Extension parameters load through the existing UnifiedParameterManager.

  • C ABI plugins return existing UpdateItem objects through PluginFunctorAdapter.

Do not add another simulator, StateManager, ParameterManager, ValidationRegistry, NodeRegistry, SSOTCatalog, port schema, extension registry, IPHS level registry, or compiler.
