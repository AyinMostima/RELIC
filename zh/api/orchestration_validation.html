编排、Contract 与 Validation API

本页记录用于描述 RELIC workflow、验证其接口、将其编译为 execution plan，并通过现有 simulator 执行该计划的 canonical public type。本页还记录同一架构使用的 variable contract 与 unified validation API。

以下签名使用 ... 表示由新的 default_factory 容器支持的字段。Canonical owner path 标识实现该类型的模块。便捷 import 标识存在时所支持的较短 import。

Graph IR 数据模型

GraphIR

权威实现：relic.orchestration.graph_ir.GraphIR

便捷 import：

from relic.orchestration import GraphIR

构造函数：

GraphIR(
    schema_version: str,
    nodes: Dict[str, NodeSpec],
    links: List[LinkSpec] = ...,
    metadata: Dict[str, Any] = ...,
    assertion: Dict[str, Any] = ...,
)

参数：

  • schema_version 标识 loader 与 compiler 所理解的 GraphIR schema。

  • nodes 将每个 workflow-local node 标识符映射到一个 NodeSpec。

  • links 包含 node port 之间的显式有向连接。

  • metadata 携带保留在 compile report 中的 workflow 级信息。

  • assertion 包含由 graph validation 评估的 structural assertion payload。DEC、IPHS、reaction-network、port、state-domain 及相关 Gate 0 检查通过此字段进入 compiler。

关键方法：

GraphIR.from_dict(payload: Dict[str, Any]) -> GraphIR
graph.to_dict() -> Dict[str, Any]

from_dict() 接受序列化的 GraphIR 形式。若缺少显式 link，它会从 {"link": [source_node, source_port]} 形式的 input binding 推断 link。to_dict() 返回对应的普通 mapping，并且仅在 assertion mapping 为空时省略该字段。

失败语义：

  • 非 mapping 的 payload、nodes value、node payload、inputs value、metadata value 或 assertion value 会引发 TypeError。

  • 非 list 的 outputs 或 links value 会引发 TypeError。

  • 缺失或为空的 schema_version 会引发 ValueError。

  • 缺少 class_type 的 node 会引发 ValueError。

  • 解析并不能证明被引用的 node 与 port 存在；这些检查由 validate_graph() 负责。

NodeSpec

权威实现：relic.orchestration.graph_ir.NodeSpec

便捷 import：

from relic.orchestration import NodeSpec

构造函数：

NodeSpec(
    class_type: str,
    inputs: Dict[str, Any] = ...,
    outputs: List[str] = ...,
    config: Dict[str, Any] = ...,
)

参数：

  • class_type 是 node-definition key、已注册的 Functor 名称，或由 execution layer 解析的可 import class reference。

  • inputs 描述 literal value 与 upstream link binding。

  • outputs 列出 node 声明的 variable 或 output port。

  • config 是传给已解析 Functor 的节点局部配置。执行器还从此映射中读取 execution_group；无论是否启用严格模式，validate_graph 都会拒绝 fast、medium、slow、None 以外的值，并使用 register_functor 抛出的错误消息（将节点的 config.execution_group 标为来源）。

NodeSpec 是 declarative record。Port type 与 unit 来自 NodeDefinition 和 SSOTCatalog，而不是此 class。

LinkEndpoint

权威实现：relic.orchestration.graph_ir.LinkEndpoint

构造函数：

LinkEndpoint(node: str, port: str)

  • node 是 workflow-local node 标识符。

  • port 是该 node 上的 input 或 output port 名称。

LinkEndpoint 未由 relic.orchestration 重新 export，因此直接构造时使用其 Canonical owner path。

LinkSpec

权威实现：relic.orchestration.graph_ir.LinkSpec

便捷 import：

from relic.orchestration import LinkSpec

构造函数：

LinkSpec(
    source: LinkEndpoint,
    target: LinkEndpoint,
)

  • source 标识 producing node 与 output port。

  • target 标识 consuming node 与 input port。

该 dataclass 不检查 endpoint 是否存在；validate_graph() 会针对完整 graph 执行该检查。

Graph 序列化

权威实现：relic.orchestration.graph_io

便捷 import：

from relic.orchestration import load_graph, save_graph

load_graph

load_graph(
    path: Path,
    *,
    validate_schema: bool = False,
    schema_path: Optional[Path] = None,
) -> GraphIR

  • path 选择 JSON、YAML 或 YML graph document。

  • validate_schema 在解析 GraphIR 前启用 JSON Schema validation。

  • schema_path 覆盖随包提供的 graph_schema.json。

当 RELIC_GRAPH_SCHEMA_VALIDATE 设为 true value 时也会启用 schema validation。无效的 JSON、YAML、schema content 或 filesystem access 会引发相应 parser、jsonschema 或 I/O exception。解码后的 root 若不是 mapping 会引发 ValueError。缺少 PyYAML 时加载 YAML 会引发 RuntimeError。

save_graph

save_graph(graph: GraphIR, path: Path) -> None

该函数将 GraphIR.to_dict() representation 写为排序且缩进的 JSON。Filesystem error 会传播给 caller。

Port 与 Node contract

PortSpec

权威实现：relic.orchestration.port_spec.PortSpec

便捷 import：

from relic.orchestration import PortSpec

构造函数：

PortSpec(
    name: str,
    standard_name: str,
    units: Optional[str] = None,
    quantity: Optional[str] = None,
    cf_standard_name: Optional[str] = None,
    element: Optional[str] = None,
    datatype: str = "tensor",
    semantics: Optional[str] = None,
    update_mode: Optional[str] = None,
    write_mode: Optional[str] = None,
    required: bool = True,
    context_requirements: Dict[str, str] = ...,
    shape: Optional[Dict[str, Any]] = None,
    direction: str = "inout",
    per_timestep: bool = False,
    conservative: bool = False,
    form_degree: Optional[int] = None,
    primality: Optional[str] = None,
    extensivity: Optional[str] = None,
    complex_id: Optional[str] = None,
    physical_domain: Optional[str] = None,
    orientation_convention: Optional[str] = None,
    boundary_role: Optional[str] = None,
    port_kind: Optional[str] = None,
    power_conjugate: Optional[str] = None,
    spatial_kind: Optional[str] = None,
    area_basis: Optional[str] = None,
    temporal_basis: Optional[str] = None,
    vertical_basis: Optional[str] = None,
    declared_support_fields: frozenset[str] = ...,
)

标识与物理语义参数：

  • name 是 local port 或 variable name。

  • standard_name 是 canonical RELIC standard name。

  • units 是由 SSOT metadata 提供的 UDUNITS-compatible unit string。

  • quantity 标识 physical quantity category。

  • cf_standard_name 在声明时携带 CF-compatible standard name。

  • element 标识 carbon、nitrogen 或 water 等 conserved element。

Runtime 与状态更新参数：

  • datatype 声明 runtime value category，默认值为 tensor。

  • semantics 区分 state、flux、tendency 或 increment 等含义。

  • update_mode 描述请求的 update operation。

  • write_mode 描述 ownership 或 mutability semantics。

  • required 标记 mandatory input 或 optional output。

  • context_requirements 声明 receiving port 所需的 conversion context key。

  • shape 携带已声明的 dimensional 或 shape metadata。

  • direction 声明 input、output 或 bidirectional use。

  • per_timestep 标记其解释与 time step 绑定的 value。

  • conservative 标识参与 conservation contract 的 port。

DEC 与结构参数：

  • form_degree 是 discrete differential-form degree。

  • primality 标识 primal 或 dual complex placement。

  • extensivity 标识 extensive 或 intensive interpretation。

  • complex_id 标识关联的 discrete complex。

  • physical_domain 命名 cochain 表示的 physical domain。

  • orientation_convention 声明 sign 与 orientation convention。

  • boundary_role 标识 interior、boundary、source 或 sink role。

IPHS port 参数：

  • port_kind 标识 port-Hamiltonian role。

  • power_conjugate 标识成对的 effort 或 flow variable。

支撑域参数（按 relic.orchestration.port_spec.PORT_SUPPORT_FIELDS = ("shape", "spatial_kind", "area_basis", "temporal_basis", "vertical_basis") 排序）：

  • spatial_kind 可取 leaf、canopy、grid_cell、footprint、tower_height 或 vertical_column。

  • area_basis 可取 leaf_area、ground_area 或 grid_area。support_aggregation 将其解释为数值和权重采用的面积度量；量的表示基准由 SSOT spatial_basis 决定。

  • temporal_basis 可取 instantaneous、interval_mean 或 interval_integral。

  • vertical_basis 可取 none、height_level 或 layer_integral。

  • declared_support_fields 列出显式声明的支撑域字段（shape 及上面四个字段）；构造时会加入每个具有取值的支撑域字段。

支撑域取值超出上述词汇表，或 declared_support_fields 含有未知名称时，会抛出 ValueError。NodeRegistry 从 SSOT 条目的 support 映射填充支撑域字段；support 不是映射时抛出 ValueError。

关键方法：

port.to_dict() -> Dict[str, Any]
port.is_support_declared(field_name: str) -> bool
port.missing_support_declarations() -> tuple[str, ...]

is_support_declared() 在名称不是支撑域字段时抛出 ValueError。missing_support_declarations() 返回未显式声明的支撑域字段。

PortSpec 是 data contract，本身不验证 compatibility。can_connect() 与 validate_graph() 拥有 compatibility decision。

SSOT 投影与 Node registry

SSOTEntry

权威实现：relic.orchestration.ssot_catalog.SSOTEntry

构造函数：

SSOTEntry(
    name: str,
    standard_name: str,
    units: Optional[str],
    spatial_basis: Optional[SpatialQuantityBasis] = None,
    quantity: Optional[str] = None,
    cf_standard_name: Optional[str] = None,
    element: Optional[str] = None,
    semantics: Optional[str] = None,
    update_mode: Optional[str] = None,
    write_mode: Optional[str] = None,
    context_requirements: Dict[str, str] = ...,
    datatype: Optional[str] = None,
    shape: Optional[Dict[str, Any]] = None,
    dimensionality: Optional[Dimensionality] = None,
    references: List[str] = ...,
    raw: Dict[str, Any] = ...,
)

  • name 是 catalog key。

  • standard_name 是声明的标准名；未声明时取键名。它与保存在 raw 中的 cell_methods 限定项共同构成该条目的 CF 标识。

  • units 与 dimensionality 描述 physical dimension。

  • spatial_basis 是声明的空间表示（intensive、cell_total、area_density 或 categorical），由 resolve_spatial_basis 根据条目的 spatial_basis 解析；否则根据值为 intensive 或 categorical 的 variable_type 解析。条目未声明这两个键时取 None；variable_type 为 extensive 却未声明 spatial_basis、存在未知值或两者不一致时，抛出 ValueError。quantity 表示物理量名称。

  • cf_standard_name 与 element 提供 standard 与 conservation tag。

  • semantics、update_mode 与 write_mode 描述 state interaction。

  • context_requirements 列出所需的 conversion context。

  • datatype 与 shape 描述 runtime representation。

  • references 保留 parameter metadata 中的 source reference。

  • raw 保留完整的 source payload，包括未提升为 direct attribute 的 structural field。

SSOTEntry 未由 relic.orchestration 重新 export。

SSOTCatalog

权威实现：relic.orchestration.ssot_catalog.SSOTCatalog

便捷 import：

from relic.orchestration import SSOTCatalog

构造函数：

SSOTCatalog() -> SSOTCatalog

工厂方法：

SSOTCatalog.from_parameter_manager(manager: Any = None) -> SSOTCatalog

  • manager 是 optional UnifiedParameterManager-compatible object。省略时使用 canonical global manager。

关键成员：

catalog.add_entry(entry: SSOTEntry) -> None
catalog.get(name: str) -> Optional[SSOTEntry]
catalog.get_by_standard_name(
    standard_name: Optional[str],
    *,
    cell_methods: Optional[str] = None,
) -> Optional[SSOTEntry]

get(name) 返回该变量名对应的条目，变量名是目录中的唯一键。否则会跟随参数表 coupling.external.variables.aliases 或变量契约中显式声明的别名，再尝试不带 cell_methods 限定项的 get_by_standard_name(name)；无匹配时返回 None。get_by_standard_name() 将由 standard_name 和 cell_methods 组成的 CF 标识（CF-1.8 第 7.3 节）视为一个键：未给出 cell_methods 的请求只选择未声明该项的条目；没有条目具有该标识时返回 None。

目录不保存冲突列表；任何冲突都会抛出 ValueError：

  • 再次声明已有变量名时，若两次声明一致则合并；若单位（无量纲的不同写法视为相同）、语义、CF 标准名、更新或写入模式、空间基准、物理量、元素、数据类型、上下文要求、standard_name 或 cell_methods 存在矛盾，则报错。

  • 一个 CF 标识只能属于一个变量；第二个变量声明同一标识时会报错。此规则由 relic.data.standards.cf_conventions.register_cf_identity_holder 负责。

  • 条目名与别名冲突、别名指向另一个已有变量或被两个变量同时占用、别名目标未知，以及别名条目不是一对非空名称，均会报错。

from_parameter_manager() 读取两个必需项 coupling.external.variables.variable_definitions 和 coupling.scales.defaults.variables，然后合并通过 load_contract_registry() 读取的随包变量契约，比较单位和 CF 标准名，最后注册可选别名表。如果契约别名指向参数目录条目，则将该条目合并到契约变量。没有可用管理器时工厂抛出 RuntimeError；缺失必需数据时抛出 KeyError；必需数据或已提供的别名表不是映射时抛出 TypeError；契约注册表报告冲突时抛出 ValueError。

Canonical owner 边界：

SSOTCatalog 是 UnifiedParameterManager-backed metadata 的 orchestration projection。它不拥有 parameter value、bounds、units 或 scientific default，也不是第二个 SSOT service。

GraphExecutor 将 ExecutionPlan 桥接到 RELICSimulator 与 StateManager。它不是第二个 simulator，也不替代 FunctorBase 生命周期。其检查点方法保持同样的唯一 owner 边界：relic.core.simulator.checkpoint 拥有 strict 的版本化 weights_only=True 文件格式、科学/拓扑/device/distributed 签名、RNG 对称性、原子写入、回滚与回执。

  • tolerance_overrides 为接受覆盖的规则提供显式数值容差。随机评分规则优先读取下列每组中前面的覆盖键，否则读取括号内名称对应的无量纲参数 validation.stochastic_scores.<key>（缺失参数会报错）：crps_warning（crps_warning_threshold）、crps_critical（crps_critical_threshold）、alpha（pit_significance_level）、brier_warning（brier_warning_threshold）、brier_critical（brier_critical_threshold）、brier_reliability_warning（brier_reliability_warning_threshold）、coverage_tolerance（coverage_deviation_tolerance）、coverage_error_alpha（coverage_error_significance_level）、coverage_warning_alpha（coverage_warning_significance_level）、interval_width_narrow（interval_width_narrow_threshold）和 interval_width_wide（interval_width_wide_threshold）。Brier 的 threshold 和 nominal_coverage 从上下文元数据读取，否则从同一命名空间的 brier_event_threshold 和 nominal_interval_coverage 读取。水、碳、能量和氮的守恒收支规则不允许覆盖其收支容差：各规则将相对残差 max_i |r_i| / sum_k |t_k,i| 与唯一对应键 validation.conservation.<budget>_conservation_tolerance 比较。缺项收支无法求值：规则返回一条 ERROR 结果，带 MISSING_REQUIRED_DATA、passed=False，不含残差，并列出缺项；绝不将缺项当作零，因此零地表热通量（例如整日步长采用 FAO-56 式 42）也须显式提供。碳规则评估已提供定义项的各恒等式（net_primary_productivity、net_ecosystem_exchange、storage_change）。氮规则闭合土壤矿质氮总量（NH4 加 NO3）：输入项为沉降、固氮、施肥和净矿化，输出及变化项为反硝化、淋失、挥发、植物吸收和储量变化；硝化是内部转移，不列为收支项。若上下文完全没有某收支的通量字典，规则返回一条 WARNING 结果，消息和详情均为 not applicable (domain absent)，表示未执行检查。碳和能量规则的合理性警告从 validation.conservation.plausibility.* 读取限值。

  • metadata 携带 execution context 与 control flag。

  • state、parameters 与 output 注入 rule input。

  • functor_name 与 functor_metadata 标识 Functor scope。

  • time 与 dt 提供 temporal context。

该 dataclass 本身不验证 scientific state。

命令行入口与运行时边界

  • python -m relic.orchestration（relic.orchestration.__main__）基于 load_graph、validate_graph 与 compile_graph 提供 validate <graph> 与 compile <graph>（支持 --strict、--auto-adapt、--output）。

  • python -m relic.interfaces.cli.main 提供七个顶层子命令：params、optimization（opt，[N]）、data、compute、stochastic（stoch）、orchestration（graph）以及 healthcheck（health）。

  • 已认证的 Level 2（[I]）随机过程（OrnsteinUhlenbeckTemperatureFunctor 与 MarkedPoissonRainfallFunctor）可通过 GraphIR 与 GraphExecutor 编译和执行，并借助 FunctorSubstreamMixin 支持检查点确定性重放。相比之下，optimization 命令行子命令处于 [N]（runtime_unbound），relic.optimization.assimilation 中的 FourDVar 则是未实现的 [N] 框架外壳，不含伴随模型（调用 compute_gradient 会抛出 NotImplementedError）。

Canonical ownership 概要

  • compile_graph() 拥有 GraphIR compilation；RELICModelCompiler 是其 facade。

  • RELICSimulator 与 StateManager 拥有 runtime advancement；GraphExecutor 将 plan bridge 到这些 owner。

  • UnifiedParameterManager 拥有 parameter 与 SSOT metadata；SSOTCatalog 是 read-only orchestration projection。

  • NodeRegistry 仅拥有 node definition。

  • ContractRegistry 拥有 variable write 与 conservation contract。

  • ValidationRegistry 拥有 unified validation rule。

  • Graph ValidationReport 描述 GraphIR compatibility 与 assertion。

  • ValidationReportModel 描述 framework-wide L1 至 L4 result。

  • 编译报告中的 adapter 插入只是元数据；只有 auto_adapt=True 会将与上下文无关的单位换算转换为可执行的 adapter 步骤。
