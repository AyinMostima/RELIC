参数与参数契约

本页记录 RELIC 使用的 canonical parameter-management API。UnifiedParameterManager 是唯一的具体 parameter manager，负责参数查找、验证、持久化、单位转换、可训练参数、缓存和 snapshot。ParameterSpec 是单个参数的 canonical metadata contract。

重要

不存在名为 ParameterManager 的可导入类。架构说明中的这一名称表示参数管理职责。Python 代码通过 get_global_manager() 获取进程级的 UnifiedParameterManager。直接构造 UnifiedParameterManager(...) 会创建独立管理器，使用时必须显式注入。

科学 FunctorBase 子类不得直接调用 global manager。它们只能通过 self.get_parameter_value("key", required=...) 获取值。非 Functor 基础设施使用 get_global_manager().get(...)。

稳定导入

from relic.parameters import (
    BoundsPolicy,
    ParameterDatabase,
    ParameterDefinition,
    ParameterSchema,
    ParameterSnapshot,
    ParameterSpec,
    ParameterStorage,
    ParameterValidator,
    UnifiedParameterManager,
    UnitValidationMode,
    get_global_manager,
    list_parameters,
    reset_global_manager,
    set_value,
)

from relic.parameters.types import (
    ParameterValidationContext,
    ParameterValidationLevel,
    ParameterValidationResult,
)

以下直接模块路径是 canonical runtime integration path，但其 package root 不会重新导出这些路径：

from relic.coupling.scales.physical_constraint_manager import (
    ConstraintSpec,
    ConstraintType,
    PhysicalConstraintManager,
)

from relic.validation.conservation_guardian import (
    BudgetCheckResult,
    ConservationGuardian,
)

relic.parameters 中的 ValidationLevel、ValidationContext，以及 relic.parameters.types 中的 ValidationResult，都是带领域前缀的参数类型的兼容别名。新文档和代码应使用上方带领域前缀的名称，避免与 relic.validation.framework 混淆。

UnifiedParameterManager

实现：relic.parameters.manager.UnifiedParameterManager

稳定导入：

from relic.parameters import UnifiedParameterManager

构造函数

UnifiedParameterManager(
    database_path: Optional[Path] = None,
    metadata: Optional[ManagerMetadata] = None,
    preload_all: bool = False,
    warmup_cache: bool = False,
    **kwargs,
)

参数

类型与默认值

用途

database_path

Optional[Path] = None

参数数据库根目录。None 选择 relic\parameters\database。

metadata

Optional[ManagerMetadata] = None

BaseManager identity 和 lifecycle metadata。省略时，manager 会创建 canonical metadata。

preload_all

bool = False

在构造阶段加载完整参数数据库，不依赖命名空间延迟加载；后续调用 initialize() 不再执行加载。

warmup_cache

bool = False

预加载后预热值缓存。当 preload_all 为 false 时，该项不会单独生效。

cache_enabled

通过 kwargs 提供的 keyword-only 参数，默认值为 True

启用参数值缓存和单位转换缓存。

cache_max_size

通过 kwargs 提供的 keyword-only 参数，默认值为 1000

参数值缓存条目的最大数量。

cache_ttl

通过 kwargs 提供的 keyword-only 参数，默认值为 None

可选的 cache time-to-live。

每次构造都会创建新的独立管理器；该类没有单例钩子。进程级管理器只能通过 get_global_manager() 获取，普通应用代码应使用它。需要独立所有者的代码应自行构造并显式注入，例如通过 Functor 的 parameter_manager 参数。注入的管理器必须公开 database，即其 ParameterDatabase：FunctorBase.get_parameter_value() 和外部耦合适配器中的点分名称解析会调用 relic.parameters.namespaces.is_declared_namespace(namespace, manager)，后者查询 manager.database.declares_namespace(...)。独立管理器绝不重写进程级变量名映射器。

在默认随包数据库（relic\parameters\database）下，138 个 YAML 文件共定义 4,751 个叶条目（134 个原生 relic 层文件含 4,642 个条目，4 个 calibrated 层文件含 109 个条目），按层级优先级解析后得到 4,643 个有效运行时参数（其中 810 个设置 requires_grad=True 的可学习参数）。参数解析受两套独立的优先级规则治理：在 ParameterDatabase 内部，后加载层按 relic、已启用的 calibrated 作用域（global、regional、site_specific）以及 add_source(...) 路径的顺序覆盖先前层；在 Functor 内部，FunctorBase.get_parameter_value(..., source_order=("manager", "config")) 默认先查询 "manager"（UnifiedParameterManager），再查询 "config"（Functor 局部覆盖项）。

get()

manager.get(
    key: str,
    default: Any = None,
    namespace: Optional[str] = None,
    units: Optional[str] = None,
    expected_type: Optional[type] = None,
    required: bool = False,
    bounds: Optional[Tuple[float, float]] = None,
) -> ParameterValue

参数

用途

key

Canonical 或可规范化的 dot-notation parameter key。

default

无法解析参数且 required 为 false 时返回的值。

namespace

在 key normalization 前应用的可选 namespace prefix。

units

请求的输出单位。单位兼容时会转换已存储的值。

expected_type

要求解析出的值匹配指定 Python 类型。

required

参数缺失时抛出 KeyError；设为 False 时返回 default。

bounds

读取标量值时使用的可选 lower 和 upper bounds。

返回解析后的参数值（不含元数据）。请求命名空间前缀（非叶键、未传入 default 且 required=False）时，返回管理器当前持有或数据库在 <namespace>. 下定义的全部键存储值所组成的嵌套映射，其成员集合与 get_namespace_parameters 一致。该映射在每次读取时新建并归调用方所有。读取操作不设校验开关：所请求的单位换算始终接受检查，传入其他任何关键字参数均抛出 TypeError。每次成功读取（包括直接存储路径）均会记入供重启契约读取的访问历史。

可能抛出：

  • 当 required=True 且无法解析 key 时抛出 KeyError。

  • 当 expected_type 与解析出的值不兼容时抛出 TypeError。

  • 无法完成请求的转换或验证时抛出单位转换或验证异常。

对于 Python 标量或单元素 Tensor，bounds 会 clamp 返回值，并在发生 clamp 时发出 UserWarning。它不会 clamp 多元素 Tensor。

get_parameter()

manager.get_parameter(
    key: str,
    namespace: Optional[str] = None,
) -> Optional[ParameterSpec]

返回完整 ParameterSpec 或 None。该方法用于查看元数据，包括单位、边界、参考文献、来源和 requires_grad。管理器尚未持有的键从数据库读取；数据库延迟加载已声明命名空间拥有该键的参数文件（见 ParameterDatabase），随后将可学习值注册到管理器的 PyTorch 参数集合。

修改与持久化

manager.set_value(
    key: str,
    value: ParameterValue,
    units: Optional[str] = None,
    validate: bool = True,
    notify: bool = True,
) -> None

更新数值，可选地执行验证，使相关缓存失效，并通知已注册观察者。key 必须指定已注册参数（已加载或存在于数据库）：未知键会抛出 KeyError 且不改变任何内容，因此拼错的键不会成为新参数。新参数须先通过 register_parameter(...) 注册。验证失败抛出 ValueError。越界行为由 BoundsPolicy 和管理器的验证配置控制；RELIC_BOUNDS_POLICY 或 RELIC_UNIT_VALIDATION_MODE 环境变量值无效时，创建管理器会抛出 ValueError。units 指定 value 的单位：数值转换为规范声明的单位，不会替换该单位；无量纲别名 "1" 和 "dimensionless" 无须转换，单位所有者无法转换的单位对会抛出 ValueError，不执行写入。set_batch(updates, validate=True, notify=True) 提交整个批次（失败时恢复所有所有者），再通知每个发生变化的键；所有键的回调失败随后合并为一个 ExceptionGroup 抛出，已提交的修改保留。

manager.set_parameter(
    spec: ParameterSpec,
    tier: str,
) -> None

将单份完整规范持久化至数据库层，并同步设置该参数的规范、存储值与实时绑定；不向管理器加载任何其他规范。形状与 dtype 相同的既有绑定保留其 nn.Parameter 对象、梯度标志与所在设备，并原地写入新值；不再可学习的规范则移除其绑定。无张量表示的可学习规范会在执行任何写入前抛出 TypeError。spec 必须是 ParameterSpec 实例，否则抛出 TypeError。加载整个数据库（如 preload_all 或切换至新 database_path）时，按同一规则为每份规范赋予存储值并为每份可学习规范建立绑定。

manager.register_parameter(spec: ParameterSpec) -> None

在现有管理器和存储层注册规范。这是数据库和扩展加载使用的底层注册操作，不创建第二个参数所有者。register_parameter 和 set_parameter(spec, tier) 使用同一 bind_learnable_value 规则，数据库重新注册也不例外：形状与 dtype 相同时保留实时绑定对象、梯度标志和设备，并原地复制数值；形状或 dtype 改变则创建新绑定，不可学习规范不具有绑定。set_parameter 要求显式指定目标 tier。

管理器快照分别原样保存各参数状态所有者的内容：parameters 保存序列化规范及声明值（保留类型和 dtype），storage_snapshot 保存存储层自身的存储值快照（尚未存储值的规范仍不具有存储值），nn_values 保存每个实时可学习 nn.Parameter 值的副本（优化器可能已使其偏离声明值），nn_requires_grad 保存其梯度标志，并同时记录设备、验证设置和单位问题。restore() 在改变任何内容之前验证整个快照：要求有 parameters 映射，存储值与规范一致，梯度标志仅对应可学习规范，且每个标志都有一个形状和 dtype 与规范一致的实时值；否则抛出 ValueError。随后恢复存储值、规范、实时值和设置；实时值可跨设备复制到原有绑定而不替换对象，快照之后创建的绑定会移除。恢复后，每个值及其类型和 dtype、每份规范均与快照时一致。

create_snapshot() 精确捕获每个参数的值（已存储的值；未存储时为声明值），并将实时可学习值保存于 metadata["nn_values"]；restore_snapshot() 将这些值原样写回仍存在的参数，不验证、裁剪或转换，同时将实时值复制到相应绑定。快照之后注册的参数保留。get_diff()、diff() 和实验差异比较都使用解析后的值：实时可学习值优先于存储值或声明值，也就是 manager.get(...) 返回的值。

list 或 tuple 类型的 dtype 可按分量逐一声明 [minimum, maximum] 数值区间对以替代单一标量区间，例如二分量参数可声明 [[223.15, 273.15], [323.15, 373.15]]。relic.parameters.spec.componentwise_bounds_errors(value, pairs) 是此类声明的唯一校验规则：参数值必须是与区间对等长的列表或元组，每个分量均为有限实数且落在对应闭区间内。越界时 validate_value() 返回违规列表，启用校验的 set_value(...) 与 FunctorBase.get_parameter_value(...) 均抛出 ValueError，不对任何分量执行截断。列表类型参数上的扁平 (lower, upper) 区间不逐分量套用。

ParameterDatabase

    base_path: Path,
    validator: Optional[ParameterValidator] = None,
)

数据库拥有两个 precedence tier：

  • relic：native framework parameter（框架原生参数）。

  • calibrated：calibration 和 optimized value。

构造时在 base_path 下创建 relic 和 calibrated 层级目录，并初始化空参数缓存和逐文件头部缓存；不建立文件索引。每次读取都遵循唯一加载计划：

  1. 原生 relic 文件（基础层）；

  3. 通过 add_source() 添加的数据源。

ConstraintSpec 在构造时解析 type，接受 ConstraintType 或对应的值字符串；其他值引发 ValueError，并列出类型。管理器在验证阶段报告未提供上下限或满足 min_value >= max_value 的有界规范。add_constraint 仅接受类型已知的 ConstraintSpec；添加约束后再改变类型，会在应用约束时引发 ValueError，不跳过任何约束。

PhysicalConstraintManager

PhysicalConstraintManager(
    constraints: Optional[List[ConstraintSpec]] = None,
    method: Optional[str] = None,
    preserve_gradients: Optional[bool] = None,
    device: Optional[torch.device] = None,
    parameter_manager: Optional[Any] = None,
)

参数

用途

constraints

初始约束规范（ConstraintSpec 条目；其他条目引发 ValueError）。initialize() 复制这些条目，因此之后添加的约束不会在 reset() 和下一次 initialize() 后保留。

method

应用策略，取 coupling.scales.defaults.physical_constraint_method 的 allowed_values 之一（clip、scale、redistribute、project）；构造或 configure 时传入其他值会引发 ValueError 并列出允许值（被拒绝的调用不改变任何内容）。

preserve_gradients

克隆数据时保留自动微分计算图连接，不分离张量。采用 clip 方法时，被裁剪元素经由 torch.clamp 获得的梯度仍为零。取值为 True 或 False（传入其他值抛出 ValueError）；设为 None 时读取参数配置。

device

Manager operation 和 adaptive parameter 使用的 device。

parameter_manager

初始化所使用的显式参数 owner；仅当其缺失时才解析 canonical 全局参数 owner。

直接构造会创建未初始化的 BaseManager/nn.Module。基础设施调用 initialize() 和 validate()。正常的状态更新通过 state_manager.physical_constraint_manager 获取已初始化并缓存的 owner。

省略显式设置时，初始化通过权威参数管理器，从 coupling.scales.defaults 解析 physical_constraint_method、preserve_gradients 和 constraint_device。缺少必需参数值时传播查询错误，physical_constraint_method 超出其 allowed_values 时抛出 ValueError 并列出允许值；initialize() 与处理其他初始化失败相同，将该失败报告为 ManagerInitializationError，保留原错误作为原因，并将管理器置于 ERROR 状态。约束操作绝不将未知方法当作 clip，而是抛出 ValueError。如果既没有管理器，也未提供全部显式设置，初始化会抛出 RuntimeError，并按同样方式报告。

显式注入的 parameter_manager 控制初始化及后续参数查找。仅当其缺失时，_do_initialize() 才获取 canonical 的 get_global_manager()。

Conservation guardian（守恒守护器）

稳定性与所有权

ConservationGuardian 是架构中命名的 canonical 第四层 domain budget checker，但不会从 relic.validation 重新导出。仅 validation infrastructure 应使用直接模块路径：

from relic.validation.conservation_guardian import (
    BudgetCheckResult,
    ConservationGuardian,
)

StateManager 拥有 commit-time state ledger，并通过其 conservation integration 调用 guardian。ConservationGuardian 是非阻塞 diagnostic checker；它不是另一个 StateManager、ledger、generic validation result 或 scientific process。

guardian.check_domain(
    domain: str,
    flux_in: Dict[str, Union[torch.Tensor, float, int]],
    flux_out: Dict[str, Union[torch.Tensor, float, int]],
    storage_before: Dict[str, Union[torch.Tensor, float, int]],
    storage_after: Dict[str, Union[torch.Tensor, float, int]],
    dt: float,
    tolerance: Optional[Dict[str, float]] = None,
) -> BudgetCheckResult

Domain balance 为：

\[ \Delta S_{\mathrm{expected}} = \left(\sum F_{\mathrm{in}} - \sum F_{\mathrm{out}}\right) \Delta t. \]

Threshold 为：

\[ \tau = \mathrm{atol} + \mathrm{rtol} \lvert\Delta S_{\mathrm{expected}}\rvert. \]

Budget 失败时会记录 error 并返回 passed=False；不会仅因 budget 失败而抛出异常。Registry、转换或 Tensor failure 仍可能传播。check_domain() 不填充 invariant_drift；该 diagnostic 会单独计算。

guardian.compute_invariant_drift(
    incidence_row: numpy.ndarray,
    flux_vector: Dict[
        str,
        Union[torch.Tensor, float, int],
    ],
    dt: float,
) -> float

对于空 coefficient row 或空 flux vector，返回零。否则 coefficient 数量必须等于 flux entry 数量；不匹配时抛出 ValueError。

Scientific module 不得在其 forward() method 中重复实现这些 tolerance 和 budget loop。Local check 仍由 FunctorBase 所有，commit-time ledger 由 StateManager 所有，domain diagnostic 由 ConservationGuardian 所有。

物理常数与 anti-redundancy 规则

物理常数只有一个 database owner：

relic\parameters\database\relic\physical\constants.yaml

Non-Functor infrastructure 通过以下入口读取它们：

from relic.utils.physical_constants import get_physical_constant

kappa = float(get_physical_constant("von_karman_constant"))
assert 0.39 < kappa < 0.42

不要在 Python 或 domain parameter file 中重复定义 physical constant。不要添加另一个 manager、parameter accessor、cache、database facade 或 compatibility wrapper。特别是，已移除的 access chain（例如 get_parameter_by_path()、_require_parameter()、require_parameter_value() 和 ParameterAccessorMixin）不属于 public architecture。
