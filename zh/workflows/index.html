RELIC 工作流

可重组集成耦合生态系统库（Recomposable Ecosystem Library for Integrated Coupling, RELIC）围绕显式状态空间演化、类型化过程组合与参数受控校准组织运行时工作流。遵循动力系统与生态学建模通行规范（状态变量表达与质量平衡步进算子、多库室与跨尺度耦合图，以及参数估计、灵敏度分析、不确定性传播与随机强迫），首次运行模拟可按顺序阅读各页，也可直接切入对应任务路线。

如何使用教程

每项任务按以下顺序执行：

  1. 复制代码前，先阅读先决条件和 canonical-owner 表。

  2. 运行最小示例，并将输出与文档值比较。

  3. 检查状态、单位、diagnostic、provenance 和所有生成文件；不得仅以进程退出作为验收标准。

  4. 执行相关负例，确认缺失输入、非法单位、writer 冲突或 assertion 失败时能够正确停止。

  5. 当前示例及其检查通过后，才进入下一页。

Notebook 执行与公开站构建有意分离。下方 batch runner 会清空并重写所选 notebook 的输出 cell，因此应先检查 worktree，并且只对确实要刷新的 notebook 使用：

cd F:\path\to\RELIC_PROJECT
conda activate RELIC
python tools\notebook_primary_audit.py --notebook-dir tutorial\primary
python tools\execute_primary_notebooks.py --pattern "01_minimal_relic_run.ipynb" --timeout 1200 --output reports\notebook_01_execution.json

选定的 notebook 全绿后，在同一份未再改动的源码树上运行完整分发套件：

python tools\execute_primary_notebooks.py --pattern "*.ipynb" --timeout 1200 --output reports\notebook_primary_execution_final.json

当执行摘要状态为 ok、没有 error output、没有无法解释的空代码单元输出、文档规定的数值检查通过，且 diff 仅包含预期的 notebook 输出刷新时，该 notebook 才可验收。分发套件前，还必须确认报告中的 notebook 数量等于 30。30 个 notebook 的完整顺序见 tutorial\primary\README.md。
