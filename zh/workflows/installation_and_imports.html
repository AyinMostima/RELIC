安装与导入

可重组集成耦合生态系统库（Recomposable Ecosystem Library for Integrated Coupling, RELIC）在 pyproject.toml 中声明包版本 1.0.0、运行时要求 Python >= 3.11、核心依赖 torch >= 2.0.0 以及可选依赖组 [dev]。

环境要求与 Conda 环境

包元数据要求 Python 3.11 及以上版本（requires-python = ">=3.11"），并依赖 PyTorch（torch >= 2.0.0）、Pydantic V2（pydantic >= 2.0.0）、Hydra（hydra-core >= 1.3.0）、NetCDF4（netCDF4 >= 1.6.0）、Zarr（zarr >= 2.14.0）、SALib（SALib >= 1.4.0）与 FastAPI（fastapi >= 0.100.0）。各类计算任务按所执行的负载类型划分至三个专用 Conda 环境：

Conda 环境

职责

RELIC

模型执行、科学模拟、参数与图校验以及依赖模型的数据准备。

dataanalysis

独立数据准备、后处理、统计分析与发表级图表绘制。

sphinx_env

Sphinx HTML 文档生成与公开文档校验门禁。

在 RELIC Conda 环境中以可编辑模式安装该软件包：

cd C:\path\to\RELIC_PROJECT
conda activate RELIC
python --version
python -m pip install -e .

仅在需要开发与静态分析工具时安装 [dev] 可选依赖项：

conda activate RELIC
python -m pip install -e ".[dev]"

Editable installation 会使导入始终指向当前 checkout。Package installation 不会初始化 simulator、加载 scientific parameters 或注册 Functors。

审计与 native I/O 前置条件

仓库门禁与 I/O 路径依赖参考 Windows 工作站上的下列本地条件。此类条件不通过 pip 安装，仅用于限定单台宿主机运行环境，不属于 RELIC 软件包定义本身。

  • rg（ripgrep）必须能在 PATH 上解析到。test\architecture 下的架构审计以及 device-policy 检查 rg "torch.cuda.is_available\(" relic 会将其作为子进程运行。使用 Get-Command rg 和 rg --version 进行验证，并在需要时将实际安装目录添加到 $env:PATH。恰好随编辑器或助手安装附带的副本不是 RELIC 的包依赖。

  • NetCDF filter plugins：pip 的 netCDF4 wheel 在 netcdf4.libs 中附带经过名称改写的 hdf5.dll、netcdf.dll、zstd.dll、blosc.dll、libbz2.dll、szip.dll 和 zlib.dll 副本，而 netCDF4\plugins 中的 HDF5 filter plugin 却按原始名称导入它们。这些库以未改写名称存在的副本必须位于 plugin 目录中，否则每次 compression="zstd" 写入（DataWriter 的默认值）都会以 NetCDF: Filter error: undefined filter encountered 失败。仅导入 netCDF4 并不能对所配置的压缩进行资格验证：在将其用于科学输出之前，请通过真实的写/读往返验证所选 filter，并在重新安装或升级 native 包之后重复该资格验证，因为这会移除这些副本。特定主机的 DLL 修复属于环境，而不属于 RELIC 源码或生成的文档。

  • RELIC_SKIP_CALIBRATED：设置为 1、true、yes 或 on 时，参数数据库 manager 会在该进程中排除已校准参数层。仓库的测试会话默认将其设为 1，并同时设置 RELIC_SKIP_LEGACY=1，因此测试运行使用未校准的层；生产运行必须保持二者均未设置，以加载校准值。公开的科学参考描述的是生产视图，包括已校准参数；因此其新鲜度检查在子进程中运行生成器的 --check，并从该子进程的环境中移除 RELIC_SKIP_CALIBRATED、RELIC_SKIP_LEGACY 和 RELIC_FAST_INIT。不要从被改动的测试会话 singleton 重新生成生产默认值，也不要为了让新鲜度比较通过而删除校准文件。

  • 实验性数据特性开关：relic.data.quality 中的占位质量控制组件在导入时需设置 RELIC_EXPERIMENTAL_DATA_QUALITY=1，relic.data.streaming 中的实验性流式处理组件需设置 RELIC_EXPERIMENTAL_STREAMING=1。标准运行模式下两者默认均处于关闭状态。

  • 测试发现：仓库的 test-runner 配置拥有发现规则（test_*.py、*_test.py、*.test.py 和 *.spec.py，importlib import mode，strict 配置与 marker）。测试套件根目录的 conftest.py 会跳过 Windows 的 nul 占位符，以及任何以点分隔的 stem 组成部分不是有效标识符的文件，包括诸如 name (1).py 之类的资源管理器重复副本。该排除是发现规则，而不是被排除副本已被执行或验证的证据。Ruff 通过 pyproject.toml 中的 extend-exclude 排除同样的重复副本。

稳定的 package 导入

在 Windows 上，可选的 NetCDF 压缩需要所选的 HDF5 filter plugin 及其 native DLL 依赖位于当前激活的环境中。在将所选压缩用于科学输出之前，请通过实际的写/读往返对其进行资格验证；仅导入 netCDF4 是不够的。替换 native 包之后请重复该资格验证。

Root package 提供主要的构造与检查入口：

import relic

print(relic.__version__)

simulator = relic.create_default_simulator(
    {
        "time_step": 3600.0,
        "max_time": 86400.0,
        "device": "auto",
    }
)

create_default_simulator(config=None) 会以空 mapping 替换 None，然后委托给 create_simulator(config)。create_simulator 负责构造 RELICSimulator；它不会初始化 StateManager 或 dependency graph。

在 library code 中，应从各 class 的 canonical public owner 导入：

from relic.core import (
    BiologicalProcessFunctor,
    FunctorBase,
    FunctorMetadata,
    RELICSimulator,
    SimulationState,
    StateManager,
    StateVariableSpec,
)
from relic.parameters import ParameterSpec, UnifiedParameterManager
from relic.parameters import get_global_manager

延迟导入

Root-level optional components 默认采用延迟解析。以下值会启用延迟导入：1、true 和 yes。

请在导入 RELIC 前设置此行为：

$env:RELIC_LAZY_IMPORT = "1"
python -c "import relic; print(relic.__version__)"

执行 import surface 诊断时，可禁用延迟导入：

$env:RELIC_LAZY_IMPORT = "0"
python -c "import relic; print(relic.get_version_info())"
Remove-Item Env:RELIC_LAZY_IMPORT

延迟模式下，AttributeError 表示名称未导出或其子包缺失；导入子包期间发生的错误原样传播。设置 RELIC_LAZY_IMPORT=0 后，子包导入失败会使 import relic 抛出异常。已知所有者时优先直接导入规范子包。

Command-module 入口

已安装的 package 未声明独立的 relic console script。请通过当前 active Python interpreter 调用受支持的 command modules：

python -m relic.interfaces.cli.main --help
python -m relic.orchestration --help
python -m relic.extensions.cli --help
python -m relic.interfaces.cli.run_layered --help

模块

范围

relic.interfaces.cli.main

统一的 parameter、optimization、data、computation、stochastic、orchestration 与 health commands。

relic.orchestration

GraphIR 验证和编译（validate、compile）；compile --run-bundle 还会写出运行包。图执行在 Python 中使用 GraphExecutor 或 compile_and_execute。

relic.extensions.cli

Extension discovery、inspection、scaffolding 与 manifest validation。

relic.interfaces.cli.run_layered

用于显式配置 state-oriented 运行的 layered runtime shell。

分层运行器不执行完整科学模型的隐式发现与注册。当需要显式完成 Functor 注册并明确状态归属权时，请使用 Python 运行时工作流。

导入诊断

安装后执行以下简短 import check：

python -c "import relic; from relic.core import RELICSimulator, StateManager; print(relic.__version__)"

常见故障如下：

故障

含义

处理方法

ModuleNotFoundError: relic

当前 active interpreter 中未安装该 package。

激活 RELIC environment，然后执行 editable installation command。

optional backend 的 ImportError

缺少该功能所需的 dependency。

安装相应的 project extra，或使用 environment 中已有的受支持 backend。

root package name 的 AttributeError

该名称不是 root export。

从 API reference 所示的 canonical owner 导入。

CUDA 初始化错误

无法解析请求的 runtime device。

使用 device: "auto"，或按照 Devices and Distributed Execution 中的说明操作。
